# Cross-Platform Smoke Evidence

Dimension 47 cannot be scored 9+ from architecture alone. CI now proves no-bundle launch/runtime readiness on Windows, macOS, and Linux, but 9+ still requires one dated manual smoke log per operating system after a tagged release produces signed artifacts.

Current harsh score: 8.2. The previous 8.6 architectural cap is not claimed until the release-gate files are committed and tag-addressable; 9+ still requires the green release readiness gate and installed-artifact smoke proof below.

Current CI runtime gate:

- `scripts/ci-runtime-smoke.ps1` launches the built executable with `DANTE_STARTUP_PROBE=1`.
- The smoke report must include `tray_ready`, `hotkey_registered`, and `native_ready` for the launched process.
- Latest proof: GitHub Actions run `25610105987`, commit `18e712a`, with runtime-smoke artifacts for Windows, macOS, and Ubuntu.

Required manual checks per platform:

1. Install the release artifact for the platform.
2. Launch the app from a clean user profile.
3. Confirm tray or menu bar presence.
4. Confirm global shortcut opens the companion.
5. Confirm screenshot/capture path reports native or degraded status in Settings.
6. Confirm input automation either works or shows a degraded platform reason.
7. Confirm onboarding, chat, close-to-tray, and relaunch work.
8. In Settings > Platform, run the updater manifest check and confirm the installed app reaches the signed manifest for the current platform.

Use `scripts/verify-release-artifacts.ps1` or `scripts/verify-release-artifacts.sh` against the downloaded release bundle before recording the smoke result.

## Readiness Gate

Run this before claiming Dimension 47 at 9+:

```powershell
npm run check:dim47-release -- -ReleaseTag v0.1.0 -FailOnBlocked
```

The command writes `docs/cross-platform-smoke/dim47-release-readiness.json` and checks:

- the checked-in Tauri updater public key is real, not the placeholder;
- required GitHub secrets for updater signing, Windows signing, and macOS signing/notarization exist;
- release workflow actions used for signing/publishing are pinned to full commit SHAs;
- macOS direct GitHub distribution requires a `Developer ID Application` identity;
- the GitHub release is published, stable, and not left as a draft or prerelease;
- the release has Windows, macOS Apple Silicon, macOS Intel, and Linux artifacts plus `.sig` updater signatures;
- `latest.json` exists on the release and was generated by the deterministic asset mapper in `scripts/generate-latest-manifest.mjs`;
- `SHA256SUMS` exists on the release and covers the release artifacts plus `latest.json`;
- release-attached trust evidence logs exist and contain the expected Windows signing, macOS signing/notarization/stapling, and Linux AppImage updater command evidence;
- GitHub artifact attestations exist for release artifacts, `latest.json`, `SHA256SUMS`, and trust evidence, and downloaded release assets pass `gh attestation verify`;
- downloaded release assets pass `scripts/verify-release-artifacts.ps1`;
- strict dated manual smoke logs exist for Windows, macOS, and Linux, with release metadata, trust-command output, and accepted runtime results.

Keep Dimension 47 below 9 until that report is green and the manual logs are from installed release artifacts, not no-bundle CI binaries.
